# 输出契约与约数 · Output Contract

规定 SPEC 长什么样、多长、返回什么结构。refiner 与 auditor 都按此执行。

---

## 一、SPEC 10 区块模板（标题固定，顺序固定）

```markdown
## 1. 目标
一句话结果 + 3–5 条可观察的成功判据（做完能看到什么）。

## 2. 交付物
清单式：每项写 名称 / 类型（代码/文档/表格/图/脚本）/ 落盘路径 / 是否可编辑 / 是否需附说明。
没有则不写"无"，写「不适用：本任务只产出对话答复」。

## 3. 受众与语气
谁用、用在哪、深度、术语密度、语言、称呼与禁忌口吻。

## 4. 输入与事实依据
使用哪些既有文件/数据/截图/URL；缺失数据如何处理（报错停止 / 用占位 / 询问）。

## 5. 边界与禁止项
不许改的文件、不许引入的依赖、不许联网/不许装包、风格禁区、范围上限。

## 6. 执行步骤
编号步骤，含前置条件、关键命令或工具、分支（若 X 则 A 否则 B）、失败回退。

## 7. 输出规格
格式、字段/章节结构、长度区间、单位与精度、示例片段（1–3 行示意）。

## 8. 质量标准与验收
3–6 条可勾选硬指标（DONE_WHEN），每条必须能被"跑一遍/看一眼"验证。

## 9. 假设与待确认
只写一行指针（如「见结构段 GAP/ASSUMPTION，共 3 缺口 5 假设」）+ 最多 3 条最关键项的一句话摘要。
完整的 GAP / ASSUMPTION 放在返回结构的独立段，**禁止两处全文重复**；若重复，按注水扣分。

## 10. 额外可选（不属于用户需求）
只在确实有价值时给出，2 条以内，明确标"可选，不做也算完成"。
```

**区块硬约束**

- 任何区块不得为空；不适用必须写「不适用 + 原因」。
- 不许出现 `TBD`、`待定`、`视情况`、`等等`、`若干`、`相关`。
- 不写"前言/背景介绍/我将如何思考"，直接进区块。
- 不含寒暄、不含"希望这对你有帮助"。

## 二、约数（Quota）

| 产物 | 区间 | 超限处理 |
| --- | --- | --- |
| SPEC 总字数 | 400–1800 字（多交付物 ≤2600） | 超出：删解释性文字，不删规格 |
| 单区块 | 30–260 字 | 步骤区块可到 400 字 |
| GAP 条数 | 0–4 条，每条 ≤80 字（四要素分行，各 ≤20 字） | 超过 4 条：挑最阻塞的 4 条，其余转 ASSUMPTION |
| ASSUMPTION 条数 | 0–8 条，每条一行 ≤40 字 | 超过 8 条：合并同类 |
| COVERAGE 映射 | 原文每句一条，`原文片段 → 区块号` | 不得省略任何一句 |
| 审计卡 | ≤320 字，固定 7 栏 | 超了先砍 PATCH 条数到 3 |
| 子智能体调用 | 每轮 1 refiner + ≤2 auditor；全会话 ≤12 次 | 到顶：主智能体自办 |
| 循环轮数 | 1–4 | 到顶：带残余假设执行 |
| 对用户可见文字 | ≤200 字（不含成品与 FULL SPEC） | 展示 FULL SPEC 时另计，正文仍 ≤200 |
| 状态行 | 1 行 | — |

## 三、返回结构（refiner 必须逐段输出）

```yaml
SPEC: |
  ## 1. 目标
  ...
  ## 10. 额外可选
  ...

GAP:
  - 字段: 输出形态
    为何阻塞: 落地位置与文件类型决定后续所有结构
    选项: ["单个 HTML 文件（推荐）", "Markdown", "Excel"]
    默认: "单个 HTML 文件"

ASSUMPTION:
  - 目标平台 Windows → 脚本用 pwsh 可跑的写法
  - 数据量千级 → 不需要分页与索引

COVERAGE:
  - R1 "帮我写个爬虫" → 区块 1、2、6
  - R2 "要能每天跑" → 区块 6（计划任务）、8（验收含定时）
```

规则：

- `SPEC` 必须完整可读，不许写"（此处省略）"。
- `GAP` 为空就写 `GAP: []`，不许省字段。
- `COVERAGE` 每条都要指到具体区块号，指不出说明漏了。
- 整份返回不得超过 3000 字；超了先砍"额外可选"和解释性句子。

## 四、定稿交接包（HANDOFF 三件套）

```yaml
FINAL_SPEC: |
  <SPEC 全文>
ASSUMPTION:
  - <默认取值>
DONE_WHEN:
  - <3–6 条硬指标，从区块 8 抽取，动词开头>
```

主智能体拿到三件套后：

1. 立即执行（不贴全文求确认）；
2. 交付时末尾 ≤3 行：用了哪些默认、哪条改动会连带改哪里；
3. 若用户事后要看规格，再输出 FULL SPEC（此时正文约数不再适用）。

---

## 五、禁止输出清单

- ❌ "我先确认一下你的需求"（该问的已在 GAP 里，其余直接做）
- ❌ 把精炼过程、子智能体原文、审计卡贴给用户（除用户明确要看）
- ❌ 交付 "方案框架 + 待你确认" 的半成品（PASS 的定义就是可执行到底）
- ❌ 用"我们""建议您可以"等咨询腔替代具体动作
- ❌ 在 SPEC 里写"根据最佳实践"而不写具体做法
- ❌ 第 9 区块与结构段全文重复（同一内容写两遍 = 注水，按 scorecard 扣分）
