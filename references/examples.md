# 端到端示例 · Examples

四个示例覆盖全部关键分支。示例里的派发文本可直接照抄使用。

## 示例 1｜极端模糊 + 一次追问（最常见）

**用户原话**：`帮我写个爬虫`

### CAPTURE

- RAW_PROMPT：`帮我写个爬虫`
- SESSION_FACTS：Windows 11、pwsh 可用、Python 3.11 已装、cwd 无相关项目、用户此前未提站点。
- 内心摘要：意图=抓数据；交付物=可运行脚本；最大歧义=抓哪、抓什么字段、怎么存。

### REFINE（refiner-1）返回摘录

```yaml
SPEC: |
  ## 1. 目标
  产出一个可在 Windows 本机直接运行的单文件抓取脚本，把目标页面中的结构化条目抓成表格文件；
  成功判据：脚本一条命令跑完、输出文件行数 >0、字段与规格一致、失败有日志。
  ...
  ## 9. 假设与待确认
  GAP：
  1) 目标站点是哪类（新闻列表 / 电商商品 / 论坛帖子 / 其他）
  2) 需要哪些字段（标题 / 时间 / 链接 / 价格 / 正文）
  3) 结果存成哪种形态（CSV / Excel / SQLite）
  ASSUMPTION：单机运行、无代理、目标站无反爬或弱反爬 → 先按静态 HTML 解析
  ...
GAP:
  - 字段: 目标站点
    为何阻塞: 解析策略与反爬方案完全取决于站点类型
    选项: ["新闻/资讯列表（推荐）", "电商商品页", "论坛/贴吧帖子", "其他（我贴 URL）"]
    默认: "新闻/资讯列表"
  - 字段: 抓取字段
    为何阻塞: 决定解析器与输出表结构
    选项: ["标题+链接+时间（推荐）", "标题+链接+时间+正文", "全部可见文本"]
    默认: "标题+链接+时间"
  - 字段: 落盘格式
    为何阻塞: 决定依赖（是否装 openpyxl）
    选项: ["CSV（推荐，零依赖）", "Excel", "SQLite"]
    默认: "CSV"
ASSUMPTION:
  - 请求频率 ≤1 次/秒 → 需内置 sleep
  - 单页列表即可，不做翻页 → 若要全量另加
COVERAGE:
  - R1 "帮我写个爬虫" → 区块 1、2、6
```

### AUDIT（auditor-1）审计卡

```
VERDICT: FAIL
SCORE: 78
DIMS: D1 13/15; D2 10/12; D3 6/8; D4 7/10; D5 7/10; D6 12/15; D7 9/12; D8 6/10; D9 5/5; D10 3/3
BLOCKERS: 站点/字段/格式未定 → D7 无法写结构；D8 缺"抓失败怎么算过"
PATCH: P1 区块 8 补验收：①10 条样例全部解析成功 ②字段数与规格一致 ③连续跑 2 次结果一致
       P2 区块 5 补边界：遵守 robots、UA 明确、不并发轰炸、单次不超过 N 页
SCOPE_CREEP: 1（"翻页全量"未标可选）
COLD_READ: "抓哪个网站？"
```

### ASK（合并成一次提问，3 问）

| # | 问题 | 选项（首个为推荐） |
| --- | --- | --- |
| 1 | 抓哪类站点？ | 新闻/资讯列表 / 电商商品页 / 论坛帖子 / 其他（贴 URL） |
| 2 | 要哪些字段？ | 标题+链接+时间 / 再加正文 / 全部可见文本 |
| 3 | 存成什么？ | CSV / Excel / SQLite |

（若用户全跳过：新闻列表 + 标题链接时间 + CSV，继续。）

### REFINE v2 → AUDIT

v2 补齐翻页标记为「额外可选」、补 3 条验收、补 4 条边界 → 审计 93 PASS → **主智能体立刻写脚本并跑通，交付脚本 + 一份 3 行使用说明**。

## 示例 2｜用户已经很详细（体现"别折腾"）

**用户原话**：
```
把 data/raw/*.csv 合并成一张宽表，输出 data/out/merged.parquet；
要求：①列名 snake_case ②日期统一 YYYY-MM-DD ③缺值保留 NaN 不许填 0
④按 order_id 去重保留最新 ⑤给出合并前后行数对比表
```

### 流程

- CAPTURE：读到 `data/raw/` 有 4 个 CSV，列结构一致（自己 `read` 确认）→ 无阻塞。
- REFINE v1：仅补 D6 步骤与 D8 验收（去重口径 = 按 updated_at 最新？→ 原文"最新"有歧义，但可从列名 `updated_at` 推断 → 进 ASSUMPTION，不问）。
- AUDIT：`PASS 91`，`GAP: []`，`COLD_READ: 无`，`SCOPE_CREEP: 0`。
- 结果：**0 追问、1 轮通过、直接开工**。

教训：详细输入下，"精炼"表现为 15 秒的规格确认，不是重写需求。

## 示例 3｜口味歧义必须问（问"决策"不问"背景"）

**用户原话**：`做一份销售数据看板`

### REFINE 发现两个真阻塞

- 受众：给老板汇报（要结论、少图表）vs 给运营日常用（要筛选、要多维）→ 决定完全不同的信息架构。
- 口径：GMV（含退款）还是净销售额 → 数字会差一截，做错等于返工。

### ASK（2 问，带推荐）

1. 谁看这块看板？`老板汇报（推荐）` / `运营日常` / `客户演示`
2. 销售额按哪个口径？`净销售额（扣退款，推荐）` / `GMV 含退款` / `两个都出`

### 注意

**不该问的**：技术栈（默认单文件 HTML）、配色（默认跟随系统深浅色）、数据源（已在 `data/` 目录里找到）——这些全进 ASSUMPTION。

## 示例 4｜循环修补（分数单调上升）

| 轮 | refiner | 审计 | 主要问题 | 动作 |
| --- | --- | --- | --- | --- |
| R1 | refiner-1 | 71 FAIL | 缺验收（D8=4/10）、scope creep 2 条、输出规格无长度 | PATCH 4 条 |
| R2 | refiner-2 | 94 PASS | 无 | HANDOFF（PATCH 一次改到位） |
| — | — | — | 主智能体执行 + 自检 DONE_WHEN | 交付 |

**教训**：PASS 后不再无理由加轮；PATCH 里若还剩"低分维度修复成本 <1 分钟"的项；反之若 PATCH 只剩措辞美化，立即停止——**循环是为了可执行性，不是为了漂亮**。用户显式说「再打磨一轮」时，才允许 PASS 之后再跑 +1 轮。

## 反例（这些做法会让流程失效）

| 反例 | 为什么错 | 正确做法 |
| --- | --- | --- |
| 把"帮我看看这个报错"精炼成"请提供完整环境信息、复现步骤、期望结果"然后反问用户 | 违反 R3：报错文本、代码文件就在上下文里 | 自己读日志和代码定位，只问"你希望修掉还是先解释原因"这类真决策 |
| 审计给 96 分但 COLD_READ 写了"数据从哪来？" | 冷读有人要问 = 不合格 | 要么补进 SPEC，要么降分并 PATCH |
| 精炼后把"做个周报"变成"搭建自动化周报系统（含数据库）" | scope creep | 保留"一份周报"，系统化只进「额外可选」 |
| 用户跳过提问，主智能体又问一遍 | 违反 R4 | 跳过即默认，直接执行并在末尾说明默认值 |
| PASS 后回复"规格已就绪，确认后我开始" | 违反 R10 | 同一个回合直接产出成品 |
