# 详细度评分卡 · Detail Scorecard

"极其详细"不是感觉，是**可打分的状态**。审计者按本卡逐维打分，总分 100。

---

## 一、十个维度（权重合计 100）

| # | 维度 | 分值 | 满分长什么样 | 常见扣分 |
| --- | --- | --- | --- | --- |
| D1 | 目标与成功判据 | 15 | 一句话说清"做完什么算成功"，含可观察结果 | 只有动词没有结果（"优化一下"） |
| D2 | 交付物形态 | 12 | 每个交付物有类型、文件名/路径、结构、是否可编辑 | 只说"给我一份方案" |
| D3 | 受众与语境 | 8 | 谁看、用在哪、语气/深度/术语密度 | 受众不明导致深度全靠猜 |
| D4 | 输入与事实依据 | 10 | 指明用哪些既有文件/数据/截图，缺失数据怎么处理 | 不写数据来源，执行时临时找 |
| D5 | 边界与禁止项 | 10 | 不能碰的文件/技术/口味/依赖，写清"不许做什么" | 只有"做好一点"没有硬边界 |
| D6 | 执行步骤与依赖 | 15 | 有顺序、有前置条件、有分支与失败回退 | 步骤缺失，执行者自由发挥 |
| D7 | 输出规格 | 12 | 格式、语言、长度、单位、示例片段 | 只写"详细一点" |
| D8 | 质量标准与验收 | 10 | 3–6 条可勾选硬指标，含反例 | 无验收，交付靠自我感觉 |
| D9 | 假设显式化 | 5 | 每条假设写"假设 → 影响"，可被用户一眼推翻 | 假设埋在正文里 |
| D10 | 可执行性与工具 | 3 | 指明可用工具/环境/命令级别动作 | 需要的能力环境里没有 |

> 合计：15+12+8+10+10+15+12+10+5+3 = **100**

## 二、PASS 门槛

```
PASS ⇔ 总分 ≥ 85
      ∧ 每个维度 ≥ 该维度分值 × 0.6
      ∧ 10 个区块齐全且非空（不适用区块写「不适用 + 原因」）
      ∧ COVERAGE 逐句覆盖原文，无遗漏/错位
      ∧ 无未标注 TBD / 待定 / 视情况
      ∧ SCOPE_CREEP = 0（或新增已标「额外可选」）
```

分数区间语义（用于对外一句话说明）：

| 区间 | 含义 | 动作 |
| --- | --- | --- |
| 95–100 | 可交付给陌生人执行，零追问 | 直接 HANDOFF |
| 85–94 | 可执行，个别细节靠默认值 | HANDOFF + 列 ASSUMPTION |
| 70–84 | 能做，但会返工 | 继续循环 |
| 50–69 | 方向对、分辨率不足 | 继续循环，必要时追问 |
| <50 | 只算复述了愿望 | 重写，不许打补丁 |

## 三、"极其详细"的三个操作测试

审计者必须实跑，不许凭印象：

1. **冷读测试**：把 SPEC 单独交给一个没有上下文的执行者，让它只回答"哪一句我必须回来问人"。答"无"才算过；答出任何一句，该维度封顶 **55%**（低于 60% 门槛，直接 FAIL），并把那句话写进 `COLD_READ`。
2. **验收测试**：只读 SPEC，能不能写出"做完了怎么验"的清单。写不出 → D8 直接 ≤ 50%。
3. **加戏测试**：把 SPEC 与 RAW_PROMPT 并排比对，逐条找原文没有的目标。找到就记 SCOPE_CREEP；>0 时总分封顶 84（无论其他维度多高）。

## 四、PATCH 写法（审计者的唯一修补语言）

不合格时必须给出**可直接执行**的补丁，格式固定：

```
P1. 定位：区块 7「输出规格」→ 缺长度与单位
    改成：正文 1200–1800 字；表格列固定为 日期/渠道/曝光/转化；金额单位元、保留两位。
P2. 定位：区块 8「验收」→ 全空
    改成：补 4 条 —— ①脚本在 Python 3.11 直接跑通无报错；②20 条样例全部解析成功；③失败重试 3 次后写日志；④输出 CSV 列名与规格一致。
```

**禁用措辞**（写了等于没写，直接判该 PATCH 无效）：

- "更详细一些" / "补充更多细节" / "建议丰富内容"
- "可以考虑" / "视情况"
- "参考行业最佳实践"（没说哪个实践）
- "优化表达"（没说改成什么）

## 五、循环收敛策略

| 轮次 | 允许的修补幅度 | 判定失败后的动作 |
| --- | --- | --- |
| R1 | 全量重写（首版） | 正常进 R2 |
| R2 | 只修 PATCH | 分数必须 > R1，否则回滚 R1 版本换策略 |
| R3 | 只修 PATCH，禁止动已 PASS 区块 | 同一维度连续 2 次 <60% → 转 ASSUMPTION 标 UNVERIFIED，不进提问预算 |
| R4 | 只做局部字句收紧 | 仍未 PASS → 收敛交付：最高分版本 + 残余假设 + 开工 |

## 六、语言与风格扣分细则

- 用形容词代替规格（"专业""美观""高效""完整"）而无量化 → 该维度扣 40%。
- 出现"等等""之类""相关""若干"等模糊量词 → 每处扣 1 分，最多扣 5 分。
- 把 ASSUMPTION 写进正文当事实陈述 → D9 归零。
- 同义反复（同一要求写三遍不同说法）→ 每处扣 1 分，视为注水。
- 出现与用户语言不符的成品文案（中文需求写英文规格）→ R8 违规，总分扣 5。

## 七、审计卡模板（固定 7 栏，≤320 字）

```
VERDICT: PASS | FAIL
SCORE: 0-100
DIMS: D1 14/15; D2 11/12; D3 7/8; D4 9/10; D5 10/10; D6 13/15; D7 10/12; D8 8/10; D9 5/5; D10 3/3
BLOCKERS: ≤3 条，指向维度或缺失区块
PATCH: ≤5 条，格式见上
SCOPE_CREEP: 0 | n（是否已标可选）
COLD_READ: 无 | "<会让人回来问人的那句话>"
```
